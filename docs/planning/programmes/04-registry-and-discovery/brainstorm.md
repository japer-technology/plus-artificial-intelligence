# Brainstorm — Programme 04: Registry and Discovery

> Companion to [`04-registry-and-discovery.md`](../04-registry-and-discovery.md). Every member suggestion is decomposed here into **definitive features** and **pre-implementation decisions**; each has one agent request in [`requests/`](requests/). Workflow: open a request, record your choices in its §1, then give the file to your agent.

## Programme-level decisions (affect more than one request)

1. **Change-feed-first cadence vs the one-business-day removal rule.** The registry's release cadence (opt-in-signatory-registry D1) and the snapshot cadence (public-snapshots-and-api D1) must both be *change-feed-first with a guaranteed daily floor*, not nightly-only: the directory's "revoked records disappear within one business day" rule and sector views' "removed in the same snapshot" rule depend on removal events propagating within a business day. This is the programme risk "snapshot cadence vs revocation urgency" made a decision.
2. **The admission/moderation gate.** Self-service admission opens only after moderation-disputes-and-appeals (Programme 8) publishes its admission rules (Sequencing gate item 4). Until then the registry admits via repo-hosted JSON + PR/email with human review for consequential decisions. Placed in opt-in-signatory-registry D2, jointly owned with Programme 8.
3. **The shared disclosure threshold (k = 10).** research-observatory owns the default disclosure threshold (k = 10). sector-and-language-directories D2 and public-adoption-dashboard D2 inherit it unless they publish a stricter per-value minimum with justification; none is proposed at launch, so all three surfaces share one threshold.
4. **§11 cross-cutting placement.** The registry self-service admission threshold + release cadence (§11) is placed in opt-in-signatory-registry D1–D2, jointly owned with moderation-disputes-and-appeals (Programme 8). The registry *governance form* is owned by governance-and-stewardship (Programme 1, its D5) and is not re-decided here; the registry *data licence* defers to licensing-and-mark-policy (Programme 1) — opt-in-signatory-registry D3. Default read-API rate-limit numbers defer to security-and-abuse-controls + cost-discipline (Programme 8) — public-snapshots-and-api D3.
5. **Multi-language standard folding.** The draft multi-language standard ([`best-practice-multi-language.md`](../../../analysis/best-practice-multi-language.md), rules R1–R16, tiers T0–T4) governs every localised surface here: page chrome follows R1 (English source of truth), R4 (per-key fallback), R12 (resolution order `?lang=` → saved preference → browser `Accept-Language` → English, only explicit choices persisted) and R13 (English stays the crawler/no-JS default). Record content (directory entries, declarations) is **T4** user-generated content — never machine-translated into "reviewed" meaning (§4.1). The snapshot pipeline publishes records as-is (no translation) and mirror labels are rendered by third-party mirrors under their own localisation, so public-snapshots-and-api and federation-and-mirrors carry no localised chrome of their own. The standard's §8 open questions (machine-draft reachability, reviewer-attribution location, T3 machine-draft maintenance, spec-site `source-version` pinning) do **not** fall in Programme 4 — they belong to the translation/document-standard work (Programme 5: translation-governance, flavour-text-localisation) and are noted here, not re-decided.

## Member-by-member brainstorm

### opt-in-signatory-registry — Opt-In Signatory Registry
- **Request:** [`requests/opt-in-signatory-registry.md`](requests/opt-in-signatory-registry.md)
- **Definitive features:** versioned, hash-pinned `registry/registry.json` (party + declaration entry types with never-reused stable IDs, submission/publication dates, `active|revoked|superseded|disputed` status, dated consent record, optional evidence labels); rendered `site/registry.html` directory page in neutral publication-date order with the self-asserted label and non-endorsement notice plus moderation/appeal links; consent-recorded admission with human review for consequential decisions (repo JSON + PR/email submission paths); correction events and revocation-as-status (never deletion) per declaration lifecycle; deterministic snapshot export contract (identical state → identical bytes); `scripts/validate-registry.mjs` for objective-only admission checks (format/syntax, public-visibility filter, consent presence); multilingual chrome on the rendered page follows the multi-language standard (R4/R12/R13).
- **Decisions:** D1 — Release cadence (joint with moderation-disputes-and-appeals, Programme 8); D2 — Self-service admission threshold (joint with moderation-disputes-and-appeals, Programme 8); D3 — Registry data licence.
- **Open questions / risks:** release cadence and self-service threshold are jointly owned with moderation-disputes-and-appeals and remain "publish later" until Programme 8's admission rules exist (D1–D2); registry data licence is pending legal review in Programme 1 (D3). Risk: "registry as endorsement gravity" — guarded by code-level public-visibility + non-endorsement filters, not prose (programme risk; IMPLEMENTATION-PLAN §11.3).

### public-snapshots-and-api — Public Snapshots and API
- **Request:** [`requests/public-snapshots-and-api.md`](requests/public-snapshots-and-api.md)
- **Definitive features:** deterministic, hash-pinned, paginated snapshot pipeline (`scripts/build-snapshots.mjs`) with a documented canonical serialisation; versioned snapshot files + sha256 manifest, old snapshots retained permanently; incremental change feeds keyed by snapshot-version pairs with removals (redaction/tombstone) as explicit events; read-only API contract (profiles, declarations, search, verification, status) documented as unauthenticated, stateless, long-lived-cacheable, with the write path unreachable through it; per-version audit log (counts/categories) that never exposes private data; schemas versioned from launch (additive within a major version) with changelog-announced deprecation notice periods.
- **Decisions:** D1 — Snapshot release cadence; D2 — Federation search endpoint; D3 — Read API rate-limit numbers.
- **Open questions / risks:** default rate-limit numbers are deferred to security-and-abuse-controls + cost-discipline (D3); the federation search endpoint is deferred until federation-and-mirrors stabilises the mirror contract (D2). Risk: a nightly-only pipeline violating the one-business-day removal rule — guarded by change-feed-first cadence (programme-level decision 1).

### public-directory — Public Directory
- **Request:** [`requests/public-directory.md`](requests/public-directory.md)
- **Definitive features:** static collection pages over snapshot data for nine collections (people, organisations, projects, declarations, registers, pilots, integrations, translators, case studies) at `site/directory/`; non-endorsement notice on every page; neutral documented ordering (publication date) with no purchasable position; minimal rows (identifiers + links only; binding kind + last-checked date where applicable); correction/revocation/abuse routes on every page including a no-account path; search over the published snapshot index; revoked records disappear within one business day; snapshot-mirrorable under the registry licence; accessibility floor + shared navigation; multilingual chrome per the multi-language standard (R4 per-key fallback, R12 resolution order, R13 English crawler/no-JS default).
- **Decisions:** D1 — Per-collection RSS feeds; D2 — Collection launch scope.
- **Open questions / risks:** per-collection RSS feeds are deferred to changelog-and-rss (D1); the one-business-day removal rule depends on the change-feed-first snapshot cadence (programme-level decision 1); chrome follows R12/R13 and records are T4 (never machine-translated). Risk: drifting into a popularity ranking — guarded by the no-scores/no-metrics must-nots and the notice.

### sector-and-language-directories — Sector and Language Directories
- **Request:** [`requests/sector-and-language-directories.md`](requests/sector-and-language-directories.md)
- **Definitive features:** static filtered view pages for sector, artifact-type, language, and coarse-region at `site/directory/` subpaths, filtering only on declared values; non-endorsement notice repeated on every view; low-count suppression ("fewer than N records") with no member-identifying counts; no inferred sectors/locations, no geolocation, no precise location (coarse voluntary regions only); no competence/endorsement/certification implication and a stereotyping review before release; versioned filter vocabulary announced in the changelog on change; industry theme pages may consume the identical neutral view data + notices as themed layers; published through the snapshot pipeline; accessibility floor.
- **Decisions:** D1 — Sector vocabulary alignment; D2 — Low-count suppression threshold; D3 — Language machine-detection labelling; D4 — Language filter vocabulary vs the multi-language standard.
- **Open questions / risks:** sector-vocabulary alignment with external classifications is deferred to standards-engagement (D1); language views treat records as T4 user-generated content per the multi-language standard (never machine-translated, no translation-status on a declared language — D4); the standard's §8 open questions are out of Programme 4 scope (programme-level decision 5); themed layers are only testable once theme-engine-and-packs (Programme 5) exists, so the "identical data + notices" acceptance criterion is asserted structurally at launch rather than exercised against a real pack. Risk: inference/stereotype creep — guarded by declared-only filters and the anti-inference must-nots.

### federation-and-mirrors — Federation and Mirrors
- **Request:** [`requests/federation-and-mirrors.md`](requests/federation-and-mirrors.md)
- **Definitive features:** mirror contract documented (ingestion, labelling, propagation duties, namespace/identity rules); mirror descriptor schema (identity, source, snapshotVersion, freshness, schemaVersion, changeFeedVersion, removalLag, compatibility `compliant|stale|fork`); mandatory source/freshness/compatibility labels on every mirror view; bounded removal-propagation window with stale/non-compliant marking; fork declaration and compatibility revocation rules; one-writer rule with mirror URLs never impersonating canonical addresses or IDs; no trust score/rank/verdict; reference ingest tooling (`scripts/mirror-ingest.mjs`) that fetches snapshots + change feeds, applies removals, and emits a self-describing descriptor.
- **Decisions:** D1 — Removal-propagation lag window; D2 — Project mirror directory.
- **Open questions / risks:** removal-lag window and the mirror-directory question are the two open items (D1–D2). Risk: "federation drift" — the descriptor/lag labels must be machine-checkable or the no-alternate-truth rule is unenforceable (programme risk); guarded by the self-describing descriptor requirement.

### research-observatory — Research Observatory
- **Request:** [`requests/research-observatory.md`](requests/research-observatory.md)
- **Definitive features:** documented research governance (proposal, review, conflict-declaration, publication process); ethical-review gate before any access, recorded per study; disclosure threshold (k = 10 default) published with findings; privacy-safe export rules (aggregated, stripped of identifiers/contacts/free-text, no raw dumps); neutral categories only (artifact type, language, status, coarse voluntary categories); anti-doxxing controls (pre-publication output review, cross-linking prohibition, reporting route); open publication of methods + negative findings linked to snapshot versions; corrections issued as versioned corrections, never silent edits; prohibition on selling/licensing individual-level or below-threshold data; findings publication follows the multi-language standard (R1 English source of truth, T2 explanatory tier).
- **Decisions:** D1 — Third-party researcher access; D2 — Disclosure threshold value; D3 — Ethical review body.
- **Open questions / risks:** third-party researcher access terms are undecided (D1); the observatory needs a populated registry to be meaningful (P3), so at launch it ships the gate and governance rather than findings; published findings follow the multi-language standard (R1/T2). Risk: research-as-surveillance — guarded by public-only data, the threshold, and anti-doxxing controls.

### public-adoption-dashboard — Public Adoption Dashboard
- **Request:** [`requests/public-adoption-dashboard.md`](requests/public-adoption-dashboard.md)
- **Definitive features:** static `site/adoption.html` dashboard with each metric's definition, data source (snapshot version), and computation; metric set covering signers, organisations, real artifacts, declarations, languages, integrations, pilots, contributions, revocations, and service health; low-count suppression ("fewer than N"); open data published through the snapshot pipeline so every number is reproducible from the cited snapshot; honest revocation/correction reporting; growth rates only with absolute numbers + definitions; no rankings/leaderboards/vanity totals; no fingerprinting/tracking; accessibility floor; metric-definition changes announced with before/after comparability notes and versioned in the changelog; multilingual chrome and metric definitions follow the multi-language standard (R1/R4/R12/R13).
- **Decisions:** D1 — Service health historical view; D2 — Suppression threshold; D3 — Reporting period.
- **Open questions / risks:** **phase tension** — the mini-plan Order ("after snapshots") and Sequencing list put this in P2, but the programme header phase line says "P3 … dashboard on real data" and IMPLEMENTATION-PLAN §7 (P4) lists the dashboard with later research work; following the Order line, the request is filed as P2 and the tension is flagged for the human. Risk: racing/vanity metrics — guarded by the no-leaderboard/no-vanity must-nots and the k-suppression rule.
